LTB AI Support Chatbot

Claude Haiku-powered chat widget embedded on lawtoolbox.com via WordPress / WPCode

⌥LawToolBox-Internal/Chatbot ⬡Azure App Service

Data flow

Client/WordPress
Azure App Service
Anthropic AI
Email / SMTP

Components — click for details

WordPress Chat Widget (ltb-chat-widget.js)
Frontend JavaScript widget injected into lawtoolbox.com via the WPCode plugin. Renders the chat UI in LTB brand colors (navy #1B365D / orange #E87722). Sends visitor messages to the backend API and displays responses in real time.
Injected via WPCode plugin on lawtoolbox.com
Azure Node.js / Express Backend
Core application server. Handles chat sessions, rate limiting, Salesforce lookups, Claude API calls, and email transcript delivery. Deployed on Azure App Service (B1 tier, Always On enabled). Auto-deploys from GitHub on push to main.
https://ltb-chatbot-g3c7e4a3hxc4fpcz.westcentralus-01.azurewebsites.net
Anthropic Claude Haiku (AI Model)
Anthropic's Claude Haiku model powers all chat responses. The backend calls the Anthropic API with a system prompt tailored to LawToolBox support. API key stored as an Azure App Service environment variable.
api.anthropic.com — model: claude-haiku-4-5
Salesforce CRM Integration
OAuth 2.0 Client Credentials flow authenticates against Salesforce to look up visitor/client records during chat. Correct login URL is lawtoolbox.my.salesforce.com (not login.salesforce.com). Client ID and secret stored as env vars.
lawtoolbox.my.salesforce.com
M365 Email Transcripts (Nodemailer)
At chat end, Nodemailer sends a full transcript to chatbot-logs@lawtoolbox.com via Microsoft 365 SMTP (smtp.office365.com, port 587, STARTTLS). Credentials stored as env vars. Allows support staff to review all conversations.
chatbot-logs@lawtoolbox.com · smtp.office365.com:587
Redis Session Management (Redis)
Redis stores chat session state and rate-limiting data. Azure's reverse proxy appends port numbers to req.ip — the rate limiter keyGenerator strips port suffixes via regex to prevent false "too many requests" errors for legitimate visitors.
Azure-hosted Redis cache instance

GitHub repository

Repo: github.com/LawToolBox-Internal/Chatbot
Branch: main
CI/CD: Azure Deployment Center — push to main triggers automatic deploy to App Service. No manual deploy step needed.
Runtime: Node.js (LTS). If running locally in WSL, Node must be installed in the Linux environment (symlink /usr/bin/node if needed).

Environment variables (Azure App Settings)

ANTHROPIC_API_KEY — Claude API auth
SF_CLIENT_ID / SF_CLIENT_SECRET — Salesforce OAuth
SMTP_USER / SMTP_PASS — M365 email credentials
REDIS_URL — Redis connection string
⚠ All secrets live only in Azure App Service Configuration → Application Settings. Never commit to GitHub.

LTB M365 Deployment Tool

PowerShell + HTML automation for provisioning Microsoft 365 tenants at law firm client onboardings

⌥LawToolBox-Internal (GitHub org)

Deployment process flow

Components — click for details

GitHub PowerShell Deployment Script
Core automation script that provisions a law firm's Microsoft 365 tenant for LawToolBox. Handles Exchange Online, Graph API, and Centralized Add-in deployment. Written for PowerShell 5.1 compatibility — stays under the 4,096-function module limit. MSAL DLL conflicts between EXO and Graph modules handled via load-order workarounds.
github.com/LawToolBox-Internal — deploy script repo
Browser HTML Command Generator
Standalone HTML file (runs in any browser, no server needed) that generates the correctly formatted PowerShell command for a given client. Staff enter the firm's domain and tenant details; the tool outputs the exact command to copy-paste into PowerShell. Eliminates manual parameter errors.
Static HTML file — opened locally or hosted on internal share
M365 Exchange Online (EXO) Module
PowerShell module used for Exchange Online mailbox and mail-flow configuration steps during client onboarding. Must be imported before the Graph module to avoid MSAL DLL conflicts. Session scope for O365CentralizedAddInDeployment requires a fresh connection per deployment run.
Install-Module ExchangeOnlineManagement
M365 Microsoft Graph PowerShell Module
Used for user, group, and application management in the client's M365 tenant. Import after EXO to avoid DLL conflicts. Handles add-in deployment via Centralized Deployment when O365CentralizedAddInDeployment scope is needed.
Install-Module Microsoft.Graph
Reference Tested Client Deployments
Script has been validated against dunlaplaw.com and kurtzriley.com tenants. Use these as reference configurations when troubleshooting a new deployment. Domain format passed to script determines tenant routing.
dunlaplaw.com · kurtzriley.com (reference tenants)

GitHub repository

Org: github.com/LawToolBox-Internal
Contents: PowerShell deploy script + HTML command generator. Both versioned together.
No CI/CD: This tool runs locally on an admin workstation — not deployed to a server. Operator must have the required PS modules installed.

Prerequisites to run

PowerShell: Version 5.1 (Windows). Do not run in PS 7+ — module compatibility issues.
Modules: ExchangeOnlineManagement, Microsoft.Graph — import EXO first.
Permissions: Global Admin or delegated admin rights on the target M365 tenant.
Credentials: Use an LTB admin account with partner delegated access, or client-provided temporary admin credentials.
ℹ If O365CentralizedAddInDeployment session is lost, disconnect all PS sessions and reconnect EXO before retrying.

LTB Salesforce Ticket Monitor

Local OAuth 2.0 dashboard for monitoring and closing open Salesforce support cases — runs on localhost, no cloud hosting

⌥LawToolBox-Internal/SF_Ticketmon

Data flow

Browser / localhost
Node.js local server
Salesforce OAuth
Salesforce REST API
Local token file

Components — click for details

Node.js Local HTTP Server (server.js)
Core server built with Node.js built-in modules only (http, https, fs, crypto, url) — no npm install required. Listens on port 8080, serves the dashboard HTML, handles the OAuth flow, proxies Salesforce API calls, and persists tokens to disk. Run with: node server.js
http://localhost:8080 — run locally on workstation
Salesforce OAuth 2.0 + PKCE Authorization
Full OAuth 2.0 authorization code flow with PKCE (S256 challenge). The /auth route redirects to Salesforce login (via Microsoft SSO/SAML), and /callback exchanges the code for access + refresh tokens. Tokens are saved to tokens.json so re-auth is not needed on every server restart.
lawtoolbox.my.salesforce.com/services/oauth2/authorize
Salesforce Cases SOQL Query
Fetches up to 50 open cases owned by the authenticated user via SOQL. Each case includes the most recent CaseComment and EmailMessage sub-query to determine who responded last (client vs. agent). Salesforce API v59.0. Stale cases (agent replied last, 30+ days ago) are highlighted in red.
/services/data/v59.0/query — SOQL with CaseComments + EmailMessages sub-queries
Salesforce Close Ticket — PATCH API
The Close button sends a POST to /api/close-ticket, which issues an HTTPS PATCH to the Salesforce Case sobject with Status = Closed. Responds immediately; the row fades out client-side. Stale rows (red highlight) have the Close button emphasized as the primary action.
/services/data/v59.0/sobjects/Case/{id} — PATCH {Status: "Closed"}
Local file Token Persistence (tokens.json)
Access token, refresh token, instance URL, and resolved Salesforce user ID are persisted to tokens.json next to server.js. On startup the server loads this file, so re-authentication is only needed when the refresh token expires. The file is gitignored — never committed. Delete it to force re-auth.
tokens.json — gitignored, lives next to server.js
Browser Dashboard UI (index.html)
Single-file dark-themed dashboard (IBM Plex Sans/Mono, no framework). Features: stats row, filter by responder type or priority, sort options, auto-refresh (1m/5m/15m), change-detection banner, Chrome desktop notifications, and clickable case numbers that open directly in Salesforce.
Served from localhost:8080 — open in Chrome after node server.js

How to run

Prerequisite: Node.js ≥ 14 installed on Windows workstation. No npm install needed.
Start: node server.js — server runs at http://localhost:8080
First use: Open http://localhost:8080 in Chrome → click Connect to Salesforce → complete Microsoft SSO login → redirected back automatically.
Connected App: Salesforce Connected App named LTB Ticket Monitor with callback URL http://localhost:8080/callback and scopes full + refresh_token.
✓ Tokens saved to tokens.json — no re-auth needed on restart until refresh token expires.

Configuration (config.local.json — gitignored)

clientId — Salesforce Connected App Consumer Key
clientSecret — Salesforce Connected App Consumer Secret
sfInstanceUrl — defaults to lawtoolbox.my.salesforce.com
Source: Copy config.example.json → config.local.json and fill in values. Consumer Key/Secret from Salesforce Setup → App Manager → Manage Consumer Details.
⚠ config.local.json and tokens.json are gitignored — credentials never committed to GitHub.
